# Project Management

## 1. Agile Development Approach

Our team followed an **Agile-style development process** during the project. Development was carried out iteratively, with new gameplay features added incrementally across different stages.

The project began as a simple **Asteroids-style arcade shooter**, where the player could only destroy asteroids using basic weapons. As development progressed, the team expanded the game with additional mechanics including enemy ships, multiple weapon systems, a stress mechanic affecting ship control, and a level progression system.

Using an iterative approach allowed the team to gradually extend the game while continuously testing and integrating new features.

## 3. Story Point Estimation

To estimate development effort, the team used **Story Points**, an agile unit used to measure the relative size and complexity of tasks.

Story points were assigned using values such as **1, 3, 5, and 8**, where higher values indicate greater implementation difficulty.

| Feature                 | Story Points |
| ----------------------- | ------------ |
| Basic asteroid gameplay | 3            |
| Missile weapon          | 3            |
| Stress system           | 5            |
| Enemy AI                | 5            |
| Level progression       | 3            |
| Shotgun weapon          | 3            |
| Space mines             | 3            |
| HUD interface           | 3            |

Estimates were discussed collectively by the team using a **Planning Poker style discussion**, where members shared their expectations of task complexity before agreeing on a final estimate.

## 4. Sprint Review

During development, the team gradually expanded the game beyond the original asteroid shooter prototype.

The initial version of the game included only:

* asteroids
* basic shooting mechanics

Later iterations introduced several new gameplay features, including:

* enemy ships with simple AI
* a stress system affecting ship control
* multiple weapon types (laser, missile, shotgun, mines)
* level progression based on gameplay time
* a HUD displaying player status

These additions significantly expanded the gameplay experience while maintaining the core arcade mechanics.

---

## 5. Sprint Retrospective

The team also reflected on the development process to identify strengths and areas for improvement.

### What went well

* The project architecture was modular, making it easier to add new gameplay systems.
* New features such as weapons and enemies were integrated successfully.
* The iterative development process allowed continuous testing of gameplay mechanics.

### What could be improved

* Earlier task planning could have improved development efficiency.
* More frequent code integration could help reduce potential merge conflicts.
* Clearer task allocation within the team could improve coordination.

Reflecting on these points helps the team improve collaboration and workflow in future development iterations.
