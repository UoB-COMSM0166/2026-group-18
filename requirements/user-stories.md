# User Stories

This document maps user stories to all 6 epics defined in `requirements/epics.md`.

## Epic-to-Story Mapping

| Epic | Story IDs |
|---|---|
| Epic 1 - Core Gameplay Mechanics | US-1.1, US-1.2 |
| Epic 2 - Stress System | US-2.1, US-2.2, US-2.3 |
| Epic 3 - Weapons System | US-3.1, US-3.2, US-3.3 |
| Epic 4 - Enemy and Asteroid Behaviour | US-4.1, US-4.2 |
| Epic 5 - Level Progression | US-5.1, US-5.2 |
| Epic 6 - User Interface and Feedback | US-6.1, US-6.2, US-6.3 |

## Epic 1 - Core Gameplay Mechanics

### US-1.1 - Ship Control

As a player, I want to control ship rotation and thrust with keyboard input so that I can navigate the arena precisely.

### US-1.2 - Collision and Survival Loop

As a player, I want collisions and survival outcomes to be processed consistently so that gameplay feels fair and predictable.

## Epic 2 - Stress System

### US-2.1 - Stress Gain from Damage

As a player, I want stress to increase when I get hit so that mistakes create meaningful pressure.

### US-2.2 - Stress Recovery

As a player, I want ways to reduce stress (for example pickups or passive decay) so that I can recover from dangerous situations.

### US-2.3 - Tier-Based Handling Changes

As a player, I want stress tiers to affect ship handling in clear and consistent ways so that I can adapt my strategy.

## Epic 3 - Weapons System

### US-3.1 - Primary Weapon Usage

As a player, I want a reliable primary attack so that I can continuously defend against threats.

### US-3.2 - Secondary Weapon Variety

As a player, I want multiple secondary weapons with different tactical roles so that combat decisions are more interesting.

### US-3.3 - Cooldown and Limit Rules

As a player, I want weapon cooldowns and limits to be enforced clearly so that weapon balance remains fair.

## Epic 4 - Enemy and Asteroid Behaviour

### US-4.1 - Asteroid Challenge

As a player, I want asteroids to spawn and persist according to game rules so that the core challenge remains active.

### US-4.2 - Enemy Pressure

As a player, I want enemies with distinct behavior patterns so that gameplay pressure evolves beyond asteroid avoidance.

## Epic 5 - Level Progression

### US-5.1 - Score-Based Level Advancement

As a player, I want the game level to advance when my score reaches defined thresholds so that progression reflects performance and feels fair.

_Note: Updated after playtesting to replace time-based progression with score-gated thresholds._

### US-5.2 - Difficulty Scaling

As a player, I want spawn rates and enemy presence to scale with level so that progression feels meaningful.

## Epic 6 - User Interface and Feedback

### US-6.1 - HUD Visibility

As a player, I want to see score, stress, and level information clearly so that I can make informed decisions.

### US-6.2 - Game State Feedback

As a player, I want clear menu, in-game, and game-over states so that I always understand the current game flow.

### US-6.3 - Control and Status Clarity

As a player, I want key controls and weapon readiness to be understandable so that I can react quickly during gameplay.
